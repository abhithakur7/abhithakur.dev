## The job

Penbook put four things that usually live on separate sites into one product: writing a story with AI help, reading other people's stories, publishing thoughts about books, and joining clubs to talk about them with other readers and with the authors.

I built it solo at Bizdesire. That meant the data model, the NestJS API, the OpenAI integration and the React screens that use them.

<Diagram />

## One backend, four surfaces

Writing, reading, content and clubs share accounts, data conventions and a deployment, but they change for different reasons. A new club feature should not be able to break the editor.

NestJS modules gave each surface its own boundary inside one deployable. For one engineer, separate services would have been overhead with no payoff. A single unstructured app would have tangled within months. Modules kept the deploy simple and the seams honest.

## Data shaped like a book

A story is naturally a document with nested parts, and it is read and saved that way far more often than it is queried across. MongoDB fit that shape without a join for every page view. Indexes followed each surface's own access patterns: the editor loads the part being written, the reader loads what is published, and feeds and club pages read summaries.

## AI that stays on the server

The writing tools call OpenAI, and every call goes through the backend. The browser never holds a key. Prompts live in server code, so changing how the assistant behaves is a backend change rather than a front-end release, and usage can be capped per user without trusting the client.

The AI is a tool inside the editor, not the product. Readers could discover, read and join clubs without ever touching it.

## Reading and community

The other half of the product was the API behind discovery and community: published stories, posts about books, club membership and the paths that connect a reader to the writer behind a story.
